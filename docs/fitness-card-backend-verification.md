Storage policies are tested with RLS enabled and authenticated SELECT/INSERT/UPDATE/DELETE grants in the platform fixture. The actual bucket enforces WebP and 2 MiB through Supabase Storage. The fixture proves policy decisions, paths and database mutations, not HTTP MIME validation or image-byte processing. Realtime publication registration is conditional on an existing `supabase_realtime` publication; the table contains only per-user revision/timestamp signals, with own-row SELECT and no client writes.

All card/access/photo mutations share one small feature-specific advisory transaction lock to establish a consistent order. Save and evidence publication require the exact current card revision; create uses revision zero. Photo storage changes increment card revision automatically, so clients must refetch before a later CAS edit. Profile identity/account-status changes notify all related participants, including viewers without their own card. Received content must stay in memory and obey the client authorization lease; server checks cannot erase images already downloaded.
